# 微信推送买卖点（全额&趋势安全 · 60 分）

## 一、它推什么

反手页 `fanshou.html` 点「**全额&趋势安全**」、周期选 **60 分** 时图上那条 B/S，同一套判据在后台每小时（每根 60 分钟 K 走完）自动跑一遍，出现买点或卖点就推一条到微信。

- 判据不另写：直接调 `bt_run_pair(..., full=True)`，与页面同一个函数、同一份预热均线、同一本金（10 万）、同一成本（单边 0.05%），不存在“页面一套、通知另一套”。
- 买卖都推：A 腿（上方标的）与 B 腿（下方标的）谁的当根出现成交就推谁，消息里带标的代码、价格、金额、原因（站上 MA5 买入 / 反手卖出）。
- 只在**当根 K 线走完**之后才判：60 分档标签是“该根结束时刻”（美股 10:30 / 11:30 … 16:00，A 股 10:30 / 11:30 / 14:00 / 15:00），进行中的那根一律跳过，避免盘中反复改口。
- 去重：`cards.db` 的 `push_sent` 表按「A|B|K线时间|方向|腿」记一行，重启、重扫、多开都不会重复推同一条。
- 每对标的**首次扫描只记基线不推送**，避免把窗口内几十笔历史成交一次性刷屏；基线之后的新成交才开始推。
- 停机超过 `days`（默认 3 天）的旧成交不补推。

## 二、怎么让它推到微信

个人微信不能直接登录推送（扫码登录个人号那类库违反微信协议、会封号），只能用公众号模板消息、企业微信机器人或飞书群机器人。编辑 `server/push.json`，五选一：

| channel | 需要填 | 怎么拿 |
|---|---|---|
| `serverchan` | `serverchan` = SendKey | sct.ftqq.com 微信登录 → SendKey，形如 `SCTxxxx` |
| `pushplus` | `pushplus` = token | pushplus.plus 微信登录 → 一对一推送 token |
| `wxpusher` | `wxpusher_app` = appToken、`wxpusher_uid` = UID | wxpusher.zjiecode.com 建应用 + 关注公众号拿 UID |
| `wecom` | `wecom` = 群机器人 webhook 地址 | 企业微信群 → 群机器人 → 添加 → 复制 Webhook |
| `feishu` | `feishu` = 群机器人 webhook 地址（可选 `feishu_secret`） | 飞书群 → 设置 → 群机器人 → 添加自定义机器人 → 复制 Webhook；若勾了「签名校验」把密钥填 `feishu_secret` |

填完**不用重启**（每 30 秒重读一次配置），双击 `测试微信推送.bat` 即可收到测试消息；`channel` 留空时只弹 Windows 桌面通知，微信不发。

其余字段：

- `pairs`：要盯的标的对，写成 `[["上方代码","下方代码"], ...]`，默认 `[["usSOXS","usSOXL"]]`。要盯别的票就往数组里加一对。
- `p`：K 线周期，默认 `m60`；`full`：`true` 即「全额&趋势安全」（一次满仓买、一次性全平卖），改 `false` 就退成「分批&止损反手&安全」（每根 1 万逐根加仓，判据也一起变成 MA5/MA20/MA85 那套）。
- `capital`：本金，默认 100000。
- `poll`：扫描间隔秒数，默认 30。
- `toast`：是否同时弹桌面通知，默认 true。
- `days`：最多向前补推几天，默认 3。

## 三、接口与验证

- `GET /api/push/test`：立刻发一条测试消息，返回 `{channel, ok, msg}`（`msg` 是各通道的原始回执，配错时看这里）。
- `GET /api/push/scan`：立刻扫一次，返回 `events`（本次将推的成交）、`baseline`（首次基线条目）、`sent`（发送结果）、`heartbeat`（后台循环计数器，>0 说明定时任务真的在跑）。
- 后台循环在 `@app.on_event("startup")` 里起，与「收盘前 10 分钟买入提醒」(`_remind_loop`) 各自独立，互不影响；推送任何异常都被吞掉，不会拖累行情主链路。

## 四、已知限制

- 后端必须常驻（已有开机自启），电脑关机/睡眠期间的新 K 线不会推（开机后按 `days` 范围补推）。
- 数据来自上游分钟 K，上游限流时这一轮取数失败会跳过（`/api/push/scan` 的 `err` 会写原因），下一轮自动重试。
- 判据按“已收盘的 K”算，所以一条买点比盘中首次出现晚最多 1 根（60 分钟）；这是“不改口”换来的代价。
- 这是一套**信号**，不是委托：不写 `orders`/`orders_live`，也不影响页面上任何持仓与收益。

## 五、落地位置

- 后端：`server/main.py` 末尾「微信推送买卖点」一节，含 `_push_cfg` / `_wx_send` / `push_scan_once` / `_push_loop` / `GET /api/push/test` / `GET /api/push/scan`。
- 配置：`server/push.json`（模板已建好，通道留空）。
- 去重表：`cards.db` 的 `push_sent(k, at)`，首次调用自动建表。
- 入口：`测试微信推送.bat`。
